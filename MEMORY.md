# Ghore, The Chameleon (crate `ghore`) — Project Memory

A 2D platformer prototype in **Rust + Bevy 0.20**. All art is generated in code; the assets are the
world sketch `assets/world.aseprite` (layout only; its reviewed bake `world.baked` is embedded in the binary)
and the user's recorded sound effects `assets/audio/*.m4a` (embedded too, see `sound.rs`).

## Vision / story

A small, evil-looking, bone-white **chameleon** wanders a post-war wasteland **searching for the
colors that war and humans destroyed**. The world starts **grayscale**; colors are meant to be
**earned back** as the game progresses. Tone: apocalyptic, chaotic, unstable — *not cute*. It's **gory**: the chameleon slashes enemies
open and gets painted with their blood (the first color in the gray world is blood).

## Running

```sh
cargo run            # dev build (Bevy deps are optimized, see Cargo.toml profiles)
cargo run --release  # fully optimized (first build recompiles Bevy: a few minutes, extra GBs)
cargo run -- diff    # what changed in world.aseprite since the last bake → report + screenshots/world-diff.png
cargo run -- bake    # world.aseprite → world.baked (after Claude has interpreted the changes)
cargo run -- diff a b  # compare any two sketches (.aseprite or .baked)
TOUR=1 cargo run     # visit spawn, bosses, every slice, every pin, overview → screenshots/tour-*.webp, quit
START=x,y EXIT_AFTER=4 cargo run   # drop the chameleon at a world spot, log where it ends up (+ screenshots/exit.webp), quit
ENDING=1 cargo run                  # play the ending (all bosses beaten)
GREEN=1 INDIGO=1 ...                # start with those bosses beaten (all colors: see "World colors"); also ORANGE=1 (beetle: shield)
HOLD=d TAP=space@1.2,k@1.3 ...     # simulated input for those tests (keys: a d w s space k shift f j g q f1-f10 f12)
AIM=-200,150 ...                    # fake mouse at that offset from the chameleon (test head/eyes/slash/spit aim)
```

**Sketch review loop:** `assets/world.baked` = the sketch state Claude last interpreted, and what
release builds embed. When the user edits the sketch: `cargo run -- diff` (debug builds also warn
"not interpreted yet" at startup / on reload) → interpret the changes (pins, styles, parallax…) →
`cargo run -- bake`. Diffs align on the origin marker, so canvas resizes aren't changes.

On the user's **Windows** machine, Rust is installed in msys2 UCRT64: `export PATH="/c/msys64/ucrt64/bin:$PATH"` in Git Bash.
If the user has the game open, `target/debug/ghore.exe` is locked (build "fails" at the copy step):
run the fresh `target/debug/deps/ghore-*.exe` instead.

Debug: **F1** = overlay (panel = strip along the bottom of the screen, three columns (the last lists the F keys): position in world / sketch px from origin / canvas px, movement, ground, slope, region/features, state/distance/direction of the boss whose lair you're in; gizmos on the color layer: player box, velocity, ground normal, foot samples, region/feature/lair/arena rects, platforms, boss line of sight, goal and planned path). **F12 with F1 on** also writes `screenshots/shot-*.txt` with the panel text — the user reports problems with these.

Controls: `A/D` or arrows = walk (the **body faces where it walks**; the **head turns toward the mouse**: pitches toward it (`HEAD_PITCH`, `HEAD_FOLLOW`) and flips back over the shoulder when the mouse is behind (`ChameleonAnim.head_side` scales the head through 0); the **eyes** do the exact look; `Player.aim` = unit vector from `chameleon::neck()` to the mouse) · `Space/W/Up` = jump (hold for higher) · `E` = eat remains (see `feeding.rs`) · `F` / `J` / left mouse button = claw slash **toward the mouse** (hold to keep slashing back to back, `SLASH_TIME` each), front or back: the swipe arm and the wave arc pivot on the front shoulder (`chameleon::slash_center(ppos, facing)`), sweeping top to bottom on the aimed side; hitbox = half-disc of `SLASH_REACH` around the shoulder on the side of `ChameleonAnim::slash_dir()` (fixed at slash start) · **powers earned from bosses** (`boss::Defeated`, kill order, saved, cleared by F8; HUD hint lists a power only once earned, plus an "EARNED: …" announcement via `boss::Beaten`): Gutter King → `Shift/K` dash (along the walking input, else the facing), Venom Mother → `Q` / right mouse button venom spit (`spit.rs`: glob toward the mouse, hurts bosses/mobs through `SpitHit`, splashes on walls), Razorwing → **air spin** (attack while airborne, not swimming, `SPIN_COOLDOWN` 2 s: one forward whole-body turn (`ChameleonAnim.spin`, `SPIN_TIME`), hitbox = fan of `SPIN_REACH` / ±`SPIN_FAN` around the body toward the aim (`chameleon::in_fan`), `SpinWave` crescents, `Player.guard` 0.5 s = untouchable without the blink; otherwise attacks in the air are normal slashes). The Sawleg → **big jump** (hold jump on the ground, release; `Defeated::leap`). The Plague Frog → **water walk** (`Defeated::wade`: water doesn't slow, tire or drown). The King Rat → breathes the sewer air; the Reaper (mantis) → **scythe claws** (wider, deeper slash); the Dambreaker (crab) → **power blow** (hold attack 3 s, release); the BattleTank Beetle (final boss) → **shield** (`G`: `Player.guard` 2 s, 20 s cooldown, `beetle::shield`). The Weaver → **wall walking** (`Player.climbing: Option<side>`: pushing into a tall wall (not a `STEP_UP` step) gets on it, gravity off; W/S at `CLIMB_SPEED`, Space = leap off (`WALL_LEAP`), pushing away lets go (`CLIMB_LOCK` before the next grab); out over the top = a hop onto the ledge; no fall damage builds; no ceilings. `ChameleonAnim.climb` turns the rig a quarter (head up, belly to the wall) and drives the walk cycle with vertical speed). All hit tests go through `ChameleonAnim::reaches()` + `blow_dir()` (bosses, mobs, curtains) · captured mouse = the OS cursor becomes a crosshair image (`CursorIcon::Custom`, drawn in code in `hud.rs`), the arrow comes back on release · `F2` = teleport to the next boss's lair · `F3` = invulnerability (`Player.god`: `hurt()` ignores everything, so no damage/knockback, void falls just return you to safe ground; HP pips turn gold; any blow (slash, spin, spit) kills a boss at once, even through its guard) · `F8` = restart (`level::restart` in `PreUpdate` re-reads the sketch — from disk in debug — rebuilds the world, sends `WorldReloaded { bosses_moved: true }` + `level::Restart`; modules reset on `Restart` `.after(level::restart)`: fresh chameleon (keeps god), colors forgotten, blood/debris cleared, camera/hit-stop/flash/tremor reset; bosses and mobs respawn from the reloaded sketch) ·
`F4` = flight (dev: gravity/walk/dash bypassed; Space/W/Up = 900-unit impulse toward the mouse, drag 3.5/s, collisions on, no fall damage) · `F5`/`F9` = quick save/load · `F6`/`F7` = less/more brightness contrast between solid ground and interiors (`terrain_art::Contrast`, in stops, default +0.5; tiles are painted as two layers — ground `Layer::Front`, interiors `Layer::Back` child sprite — tinted live) · `P`/`Pause` = pause; `F10` = full-map WebP export to `screenshots/` (painted plain export uses current contrast; annotated export uses flat slate/charcoal on near black without waiting for textures; painted export has twice the annotated resolution, capped at 16383 px, lossy WebP quality 90; annotated stays up to 8192 px and lossless WebP, no parallax; F1 enables larger region/feature notes, creature proportions and spawn shares, and solid boss/player spawn squares with top legends; shows section progress, then presents a compression notice for two frames before encoding on a worker; elapsed real-time feedback keeps updating and the game stays responsive) · `F12` = lossless WebP screenshot to `screenshots/`.

⚠️ `target/` takes ~4–5 GB. The first build once filled the disk (ENOSPC) — keep ~8 GB free.

## Code map (`src/`)

| File | What it does |
|---|---|
| `main.rs` | App setup, window (1280×720), plugin registration; runs `sketch_tool` first when arg 1 is `bake`/`diff`. |
| `shapes.rs` | Vector-art toolkit: Catmull-Rom curves (`smooth_closed/open`), `fill` (triangle fan from centroid), `stroke` (ribbons with width/shade/pattern), `triangles`, `gradient_rect`, `ellipse_pts`, `rock_pts`, `scale_color`, and a seeded xorshift `Rng`. |
| `chameleon.rs` | The character rig, built from meshes in a bone hierarchy (`Part` enum: Rig, Body, Head, Leg{Hip/Knee/Foot}, EyeCone, Pupil). Procedural animation: walk cycle, body bob/breathing, curling tail (mesh regenerated every frame), darting eye, claw slash (near front leg, `Leg{swipe}`; `slash_pose`, faint crescent `SlashWave`), hurt blink, camouflage. `ChameleonAnim::striking()` + `slash_id` drive hits. Death pose (rolls belly-up, legs twitch). `ColorEarned` message → appended to `ChameleonAnim.earned` (kill order) and every chameleon mesh moves to the color layer. **All earned colors show at once**, one `Slot` per color in kill order (room for 11, big areas first): Torso · Head (+ lids) · Tail · Legs · Spikes (back crest + casque spikes + ridge) · Stripes (flank) · Belly (underside `band` below the belly line, + the line) · Throat (`band` under the jaw) · TailRings (`tail_rings`, hidden until earned) · Eye (turret + brow) · Scars. A slot not earned yet wears the torso color's tones (`palette`). Each piece has a `Tone` (Base/Shadow/Light/Accent); `SkinMaterials` holds one material per (slot, tone), eased in Oklab by `camouflage` toward `skin_color()` (an earned marking shows bright, not darkened; camouflage pulls everything 0.8 toward the ground color). |
| `sketch.rs` | Minimal Aseprite reader (RGBA only; layers with Normal/Multiply blend, hidden layers/groups, slices) → `Sketch`: per-pixel `Cell` (Air/Solid/Back), `Marker`s (blob centroids), `Slice`s. Marker pixels take the cell of what surrounds them. `Sketch::bake` = compact zlib'd RLE format (magic `CAMSKT01`); `decode` reads both. |
| `sketch_tool.rs` | CLI run from `main` before the App when arg 1 is `bake`/`diff`: bake, diff (origin-aligned; cell changes clustered in 8-px blocks → bbox, counts, slices; marker/slice changes), tiny PNG encoder (miniz + CRC32). `warn_if_new` (debug) is called by `level.rs` on load/reload. |
| `terrain.rs` | `Terrain` resource built from the sketch (cropped + `MARGIN`): grid queries for collision (`box_hits/box_top/box_bottom`), `surface`, `rest`, `landing`, `raycast`, `flat_span`, `clearance` (distance to solid), `distance_field`, areas (`area_at`, `style_at` → `Style` from slice names by keyword). `PX` = 8 world units per sketch pixel (tuned by the user after playtesting 5 and 10), `STEP_UP` = 2 px. Spawn / boss positions from markers. |
| `outline.rs` | Mask → traced pixel-corner loops → 1-px stairs collapsed to ramps → Douglas-Peucker; `rasterize` = antialiased even-odd scanline coverage. |
| `terrain_art.rs` | Paints the terrain into 768² sprite tiles (3 texels/px, z −1; patterns and light scaled by `K` = PX/5 so they keep their world size): coverage from `outline`, light from above (`under` depth), lit rims, per-`Style` materials (concrete cracks/strata, junk mosaic with tires, sewer brick + slime, park soil), dark interiors for Back cells. `TerrainPart` marks everything rebuilt on reload. **Progressive**: `spawn` clones the `Terrain` and prepares fields/outlines on the `AsyncComputeTaskPool` (`CanvasTask`), then paints each tile there, nearest to the focus (spawn, or the player on hot reload) first; tiles appear when ready (`finish_tiles`). Pending tasks are `TerrainPart`s, so a reload cancels them. Newer regions' materials live in `src/terrain_art/<region>.rs` (`GROUND`, `material`, `rim`, `interior`). |
| `terrain_props.rs` | Decoration along the terrain per `Style` (rebar, tires, pipes, benches…; no collision, `TerrainPart`). **Progressive**: sites are found on the task pool, then `place_props` visits them within `BUDGET` (4 ms) per frame, always in key order (same result whatever the frame rate). Sites need room to move, not open sky: interiors (Back cells) count as open for edges/walls/ceilings, and props over an interior get the `INDOOR` depth. Newer regions (`Subway`, `Treatment`, `Sinkhole`, `Catacombs`, `Mall`, `Dam`, `Bunker`, `Cave`) place props through `Hooks` in `src/terrain_props/<region>.rs`. |
| `regrowth.rs` + `terrain_props/vines.rs` | **Colors returning to the world.** Vines (climbing walls, draped over ledge lips, hanging from ceilings) are placed on top of the normal props, where `vines::share` allows (inside the region slice that holds the wasp marker): value-noise patches (~420 u) of damp, weighted by open sky over the spot and beside it (`vines::sky`: rays up, sparse in general, thickest in the open; deep interiors nearly bare), faces turned away from the sun (sun is on the left), and low = damper; plus vines draped from the top of big blocks over their faces (`vines::facade_vine`: the open sky of the lair has no surfaces, so facades fill it) and a per-450-unit-block minimum (`vines::starved`, grows as patches), plus dark ivy (`vines::backdrop`, via `facade_spots`) on the Back-cell walls of interiors. Each vine is two copies: dead/gray on the world layer, and a lush green copy on the color layer (own `ColorMaterial`s, alpha 0, `Visibility::Hidden`, `regrowth::Vine { dist }`). `regrowth::regrow` watches `Defeated`: once the Wasp is in, the colored copies fade in as a wave from the wasp's home (`DELAY` 0.8 s after the kill in virtual time, `SPEED` 700 u/s, `BAND` 350); F8 clears `Defeated` and the world rebuilds gray. Pattern for the next boss colors: a second copy of the props on the color layer + a wave. Other regions get sparse clumped hints of green (`terrain_props/moss.rs`, per-`Style` `Theme`: hue/lightness/chance/wet; weeds, moss mounds/patches, hanging moss, slime pools/drips; each hint its own hue/lightness; same gray+color-layer pair and `Vine` wave). The wave accelerates (`SPEED` + `SPEEDUP`·t) because the world is ±16000 units. moss.rs has region-specific tables (`table(style, kind)`: saplings/bushes/tire weeds/slime falls/ferns/reeds/lichen rosettes/…). Lightning only flashes when sky is open above the camera box (`atmosphere::lightning`, `open`). Yellow (Gutter King) mirrors green: `moss::Tone::Yellow` hints (`table_yellow`, 4x denser near his home), sulfur vents (`moss::vent` + `fumes.rs` `Fumer`), plus feel-the-change effects in `regrowth.rs` (screen Tint, wave-arrival flash/shake) and `fumes::ambient` (drifting fumes / green spores). `foreground_pieces` (atmosphere.rs) themes the near blurry silhouettes per style. Cave/catacombs get moss only (no grass/ferns). Dev: `GREEN=1`/`YELLOW=1` start with the wasp beaten. Note: the color layer draws over everything gray (terrain tiles, mobs) whatever the z. |
| `gore.rs` | Blood. Messages `Bleed` (spray drops) and `Paint` (splats on the claw). `Fluid` = Green (wasp blood) / Red (chameleon) / Venom (darker green than the blood; the boss glob is also on the color layer). Sticky drops touching a `PaintTarget` (ellipse on body/head/claw bones) become `Splat`s parented to that bone; drops landing on platforms become `Stain`s parented to the platform (on the terrain: free `Stain`s marked `TerrainPart`). Stains are decals on any face (floor, wall, ceiling, platform sides/underside): `contact` finds the entry point + a smoothed normal, the decal is rotated to it, and its mesh comes from one of `TILTS` (24) pre-built tilt buckets whose drips follow gravity (run downhill along walls/slopes, seep into floors, hang off ceilings). Only `STICK_CHANCE` (40%) of sticky drops stick; `PaintTarget.clear` keeps a circle clean (the eye) so the face stays readable. Splats drip then dry over 25 s; caps: 50 splats, 320 stains. |
| `boss.rs` | Shared boss machinery. `BossKind::ALL`: every boss with a sketch marker is always spawned, **asleep in its `Lair`** (the slice holding its marker ∪ its arena); entering its **arena** wakes it (`Lair.arena`: the roach's floor span, the wasp's open `chamber()` flood-filled around its marker; `Boss.awake`, its AI hunts); leaving the lair or getting `LEASH` away despawns and respawns it asleep at home; dead bosses stay dead; `Respawned` resets living bosses; **F2 teleports** to the next boss's lair (in `boss::VISIT_ORDER`, ending with the frog, the crab, then the beetle (the final boss); a new boss must be added there too). `Arena` (floor/left/right/home) found per boss by `Arena::find` around its sketch marker (`flat_span`). `Boss` component + per-boss `static SPEC: BossSpec` (name, hp, radius, blood `Fluid`, earned color, aggro). Does slash hit detection (`chameleon::SLASH_CENTER/REACH`), blood/paint, `BossHit` message (per-boss AI reacts), death spectacle (freeze → slow-mo, zoom punch, flash, 240-drop burst, `ColorEarned(spec.color)`), material flash, heal on `Respawned`, `BossStatus` for the HUD, `Gib`s via `tear_off()`, shared `hurt_player()` and `floor()` (terrain + platforms). `BossStuff` marks projectiles/gibs (cleared on swap). **Introduction**: a boss that introduces itself hides its health bar until it has been on screen and done its intro. **Answering back**: hits in a row build up (fading over time); enough of them and it stops flinching and answers with an attack or gets out of reach, then shrugs off stagger for a while (armor). |

## Key design decisions

- **The world is a sketch** (`assets/world.aseprite`, 4096×2048 RGBA). Colors, not layer names, carry meaning:
  white = solid, dark gray (Multiply layer over white) = passable structure / interiors, black = air,
  **magenta cross = world origin (0,0)**, red = player spawn, yellow = Gutter King, green = Venom Mother, dusty blue `#7f9fd6` = The Weaver (spider, matched exactly ±2 like the dragonfly's), dusty pink `#d1b0c6` = Razorwing (dragonfly; its own color, matched exactly ±2 in `sketch::decode` since it's too unsaturated for the channel test). Brown `#8f563b` = The Sawleg (grasshopper; exact match too, else it's background structure). Violet `#b800ff` = The Plague Frog (matched exactly ±2 before the channel test, else it would read as the origin's magenta; `cargo run -- mark frog x,y`). Dull red `#ac3232` = The King Rat (exact ±2 before the channel test, else it would read as the player's red; `cargo run -- mark rat x,y`). Cyan `#00ffff` = The Reaper (mantis; exact ±2 before the channel test, which has no cyan class; `cargo run -- mark mantis x,y`). Dark blue `#5b6ee1` = The Dambreaker (crab; exact ±2 before the channel test). Orange `#ff8100` = The BattleTank Beetle (exact ±2 before the channel test, else it reads as the player's red). `MarkerKind` order is the baked format's index: new kinds go **at the end** (Crab = 15, Beetle = 16). **Gotcha**: `world.baked` predates the rat (Rat was inserted before Falling, so baked Falling markers (index 9) now read as Rat, and the rat blob was baked as a second Player): re-bake once the pending sketch edits are reviewed.
  Slices are prefixed: **"region: …"** = areas (art `Style` by keyword, boss lair) and **"feature: …"** = special
  spots described in words, handled by keywords (`terrain.features`): "slippery"/"sliding"/"one way down" → slide-only
  slopes; "fall apart"/"crumbl" → junk debris while sliding (`features.rs`); "dash" gaps → no bridge, the player's dash
  (Shift/K) crosses them. Pins (`level::PINS`) are origin-relative sketch px, not slice-relative (slices get renamed). 1 px = 8 units; 1 px rise = ramp, 2 px = stair
  (auto-climbed), 3–10 px = a jump (max jump ≈ 17 px high, ≈ 22 px across). The user edits by color and expects Claude to
  interpret the shapes (art, parallax, where to put moving pieces). The user annotates intent in slice
  names: "sliding" / "one way down" makes that area's slopes (> `SLIDE_SLOPE`) slide-down-only — don't add
  ways back up there. Area colors (camouflage: `terrain_art::ground_color`) are Claude's to choose; sketch
  colors are only for markers, unknown colors are ignored. A boss marker moving on reload restarts the fight. After a sketch change: run the tour,
  check pins still make sense (a buried pin logs a warning), adjust `PINS` / `Style` keywords.

- **Grayscale is a camera setting, not data.** `WORLD_SATURATION` in `camera.rs` (0 = gray, 1 = full
  color). All colors in code stay intact so they can be "earned back" (e.g. animate saturation, or
  later move to per-object color).
- **Camouflage is gated:** `UnlockedColors` resource (in `chameleon.rs`) starts empty. The chameleon only
  blends toward a platform's `color` if that color is unlocked
  (`unlocked.0.push(level::lost_colors::PINK)`). Blending is done in Oklab.
- **Skin tinting:** meshes carry grayscale vertex colors (shading); `ColorMaterial` multiplies them, so
  the 4 skin materials (`base/shadow/light/accent`, derived by `palette()`) can be re-tinted at runtime.
- **Chameleon local coords:** faces +X, origin = collider center; the rig is flipped by scaling X
  (smoothly, reads as a turn) and scaled by `player::SCALE`.
- **System order:** `unstable::move_platforms` → `player::move_player` → chameleon animation / camera
  follow; `parallax` runs in `PostUpdate` before transform propagation.
- Z layers: sky −100 … skylines −95/−90/−70 … smoke −55 … terrain tiles −1 … platforms 0 … player 10 … ash −10/30 …
  bottom fog 35 … foreground wreckage 45 … lightning flash 80.

- **Blood is on the color layer**, so it's drawn over *all* of layer 0 (incl. fog/foreground wreckage).
  Splats are separate meshes parented to the chameleon's bones; `RenderLayers` is not inherited, set it per entity.
- The HUD has its own camera (order 2, `RenderLayers::none()`, `IsDefaultUiCamera`), so no grading ever touches it (the ending grades the color cameras too). The underlay and overlay cameras carry `camera::ColorCamera`; `camera::world_grading()` = the main camera's gray grading.
- Use `With<MainCamera>` (not `Camera2d`) in camera queries — there are two 2D cameras.

## Bevy 0.20 API notes (learned while building)

- `TextFont { font_size: FontSize::Px(18.0), .. }` (not a plain f32).
- `PrimitiveTopology` from `bevy::render::render_resource`; `Indices` from `bevy::mesh`.
- `AlphaMode2d` from `bevy::sprite_render`; `ColorGrading`/`ColorGradingGlobal` from `bevy::render::view`.
- Parenting via `ChildOf(parent)`; `Single<...>` queries; `MessageWriter<AppExit>`.
- Screenshots: `commands.spawn(Screenshot::primary_window()).observe(save_to_disk(path))`.
- Mesh2d has no backface culling, so negative scale (flipping) is fine.
- Messages: `#[derive(Message)]`, `app.add_message::<T>()`, `MessageWriter::write`, `MessageReader::read`.
- `RenderLayers` from `bevy::camera::visibility`; non-HDR 2D tonemaps/grades in-shader, so a 2nd camera
  with `ClearColorConfig::None` and no `ColorGrading` keeps colors.
- `Time<Virtual>::set_relative_speed` is handy for slow-motion screenshots.
- The default font has no arrow glyphs (←/→ render as boxes).

## Workflow tip

Prefer the built-in test hooks (`TOUR`, `START`/`EXIT_AFTER`, `HOLD`/`TAP`/`AIM`). For anything else,
temporarily add a `PreUpdate` system (after `bevy::input::InputSystems`) that presses keys via
`ResMut<ButtonInput<KeyCode>>`, takes a `Screenshot` at frame N, then writes `AppExit`; mark it
`TEMP-AUTOTEST` and remove it afterwards. To hold a jump, don't release the key the next frame
(variable jump height cuts it short).

⚠️ On macOS, screenshots come out solid black (~57 KB PNGs, HUD missing too) when the game window is
hidden / on another Space: that's the environment, not a bug. Verify through `eprintln!` logs instead.
